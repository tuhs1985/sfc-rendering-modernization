### Call paths and the batching boundary

CONFIRMED native return sites0x006A88E7/0x006A88A2 lie in the existing
0x006A8860texture-resource binder (Device3 SetTexture, vtable+0x98).
0x0069E6F2/0x0069E61B and0x0069EC3E/0x0069ECB2 are render-state contexts
(Device3 SetRenderState,+0x58; alpha-blend and depth controls). Native pending
batch handling and the observed downstream callback support a **flush-context**
interpretation. These stacks do not identify the producer of already queued
geometry, nor necessarily the resource being selected by the incoming call.

## What the new observer adds

Enumerated full-rate metadata through the copied game's D3D11/full-support ReShade
chain: existing device/resource/view/command/target/draw/clear/copy/resolve/Present,
viewport/pipeline/dynamic-state/execute events, plus texture/sampler/buffer-range
bindings, vertex/index-buffer identities/strides, scissors, static blend/depth/
rasterizer/topology descriptors, pipeline retirement, descriptor-table identities
and constant range metadata. **No payloads** from geometry, image, shader or
constant resources; no new game renderer, effects renderer or geometry hook.

Raw call origins: sample every64th admitted draw, up to8stack walks per observed
Present interval, max32return addresses. Native x86 observer preserves its own
frame pointers; ordinary upstream modules are not modified. Resource creation/
pipeline descriptors are not evidence of exact gameplay owner. Module ranges
are polled outside callbacks and are not exact module unload timestamps.

Classification output groups draws by pipeline, depth/view/resource epochs,
texture references, dynamic state, vertex layout and index format. It reports
first/last observation, transitions, five-second count windows, sampled caller
addresses/modules, resource retirement/reuse and explicit unknown owners.
Transient buffer offsets are retained in raw events, not used to manufacture a
new rendering family for every upload. Same graphics state is **compatible with**
sharing a path; it is not sufficient to identify semantic effect type.

## Required interpretation after gameplay

1. Establish actual trace duration, positive/zero-work draws, bytes, drops/caps,
   descriptor truncation, analysis-table saturation and source/module coverage.
2. Compare quiet/camera/combat intervals using observed state/resource/lifecycle
   changes. Cue time records requested activity, not proof that activity occurred.
3. Resolve sampled call addresses to observed module ranges; identify return
   sites in SFC where present. Use existing static boundaries/anchors only with
   explicit confidence; do not blindly name a function from the nearest string.
4. Join resource-view creation epochs to texture/buffer bindings and draw state.
   Reused handles cannot revive retired resources. Preserve unjoined activity.
5. Distinguish actual upstream-owner evidence from same-thread temporal/resource
   correlation. Translation, batching or deferred execution can sever the join.
6. Update this table with concrete signatures/intervals/call sites. If an effect
   was not visible or had no identifiable signature, retain it as uncovered.

## Smallest extension candidates — recommendations only

**First candidate:** add explicit ordered material/draw-state descriptions to the
neutral scene contract: blend/depth/cull/topology plus screen/world coordinate
space and resource-epoch references. Existing rigid-mesh submission must not
silently approximate additive/alpha effects. Actual surveyed use determines which
fields are needed first; do not implement a generalized new renderer now.

**Conditional second candidate:** a bounded transient primitive/effect batch
(quad/ribbon/line/colored triangles) with observed owner/producer, geometry update
and spawn/retire semantics, **only if** the survey demonstrates it is distinct
from existing retained meshes. Shared low-level indexed draws alone are not
enough to reuse the ship contract.

**Conditional targeted captures:** one Q3-resource-to-batch join; one beam-endpoint
producer; one damage-material revision; or one grid/UI ordering boundary. Select
the smallest unresolved relationship from actual evidence, not all at once.
Leave original tactical UI/effects intact while those relationships remain open.

Unresolved deferred command replay/descriptor-table contents/OS cursor activity
are coverage limits, not absence of rendering. No formal TRL, full-scene support,
replacement or universal effects-coverage claim.
