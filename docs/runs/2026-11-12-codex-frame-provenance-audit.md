# Frame provenance audit before merging the rapid-pan fix

Reviewed the shipped multi-ship native-insertion path, its development equivalent and other callers of the Remix output-copy API. The defect found in the rapid-pan investigation was a completed copy of the wrong swap-chain image. A fence and matching frame metadata cannot by themselves identify the pixels copied.

## Active path

| Boundary | What establishes identity or freshness |
| --- | --- |
| SFC simulation and camera to scene packet | The first qualified native wrapper samples the active camera and reads current pose inputs for each retained owner. Unstable or unavailable poses are omitted. The completed scene snapshot includes a common camera, exact frame, owner/revision, and damage state before the renderer wakes. [Capture](../../tools/m1_component/m1_live_scene.h) · [Packet validation](../../tools/d3d9_proof/multi_scene_wire.h) |

## Same assumption in diagnostic paths

- The ordinary D3D9 host's optional `SFC_DIRECT64_BACKBUFFER_DIAGNOSTIC` readback runs after `PresentEx`. It reads render target 0 and names the file with the current iteration. Treat those images as post-Present snapshots with unverified frame identity. They cannot independently establish that an exact frame was submitted correctly. The separate ordinary replay captures its colour and mask before Present. [Host diagnostic](../../tools/d3d9_proof/d3d9_direct_host.cpp) · [Ordinary replay](../../tools/d3d9_proof/d3d9_replay.cpp)
- The parked API host and the earlier SDK output, coverage and ship-live probes also use post-Present `FINAL_COLOR` copies. Their swap-chain modes and runtime versions can differ. Their exact-frame comparisons need their own marker proof before reuse. The packaged launcher uses the native all-ships path. Its `return_host` process runs in observation mode and does not enter that binary's image-producing branch. [API experiment](../../tools/remix_api_proof/api_host.cpp) · [SDK probe](../../tools/remix_runtime/output_probe.cpp) · [Observer startup](../../src/session/coordinator.py)

No second wrong-frame handoff was identified in the active path by source review. The audit ran 75 Python tests across native insertion, lights, debris and damage, 193 native cohort checks on each architecture and 649 game-output wire checks. The debris integration fixture required access to the current-user mapping and passed on rerun. These checks cover the contracts and fixture cases, while the rapid-pan marker experiment supplies the pixel-origin proof for the pinned runtime. No new gameplay or GPU capture ran in this audit.

Before merge, qualify the corrected pinned adapter in the package. Include the first delivered tactical frame and the first frame after a target reset in the frame-marker check. The resize/device qualification predates the correction and the 1080p live test did not recreate its target. Keep the optional post-Present probe out of exact-frame sign-off until it has its own marker result.
