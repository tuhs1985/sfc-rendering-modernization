# Run235 — unused callbacks and repeated validation removed from native insertion

Sponsor authorized removal of unused callbacks and duplicate checks from normal play, following the runtime-checks audit. This increment implements C07 and the receiver/compositor portions of C09/C10. No appearance, timing policy, source capture, rendering architecture or original asset changes.

## Changes

- **C07:** native insertion no longer registers legacy direct-game draw, indexed-draw and depth-clear observers when foreground replay is off. These callbacks immediately did nothing in the established native mode. Legacy depth workflows and explicitly requested foreground replay retain their observers. Registration and removal use the same frozen policy. Present, resource/runtime lifetime and explicit native insertion dispatch remain intact; native drawing itself is untouched.
- **C09:** the first acquisition still coherently copies and validates the full 12,328-byte scene snapshot, then qualifies output membership/catalog identities at the transfer boundary. Later owners sharing that immutable output lease use the receiver's retained private snapshot and cheap frame/sequence/hash/owner/revision/model/source/thread matches. They no longer reread, checksum and validate the full shared scene for each owner. A frame whose acquisition already failed also avoids repeating the full read for later owners. Invalid source qualification does not consume the frame's acquisition attempt. New-frame lease closure and GPU completion are unchanged.
- **C10:** the compositor retains one validated target/depth view pair and two validated input-view sets, matching the fixed output pool. Device identity, formats, dimensions, samples and view descriptors are checked on first use/change. Strong COM references keep cached identities alive, preventing recycled pointer addresses from qualifying new resources. A new compositor/device starts with empty caches; changed targets/views trigger qualification. Failed checks never populate a cache. Per-draw key/owner/viewport bounds and input/target alias checks remain. No new images or GPU surfaces are allocated by the caches, only bounded references to existing resources.

Full catalog/manifest validation was already performed when acquiring an output lease; it was not removed. C05/C06 detailed evidence toolset separation, C08 matrix compatibility caching, and C11–C14 asset/deployment cleanup remain separate work. This is not a claim that all diagnostics have been removed from performance mode.
