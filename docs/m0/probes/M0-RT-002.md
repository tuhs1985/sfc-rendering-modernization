# M0-RT-002 — Semantic Source and Polygon-Owner Correlation

## Technical question

What stable object or ownership chain initializes and invokes the graphics
manager polygon-preparation method immediately above confirmed generic
submission at `0x006AB410`, and do its arguments retain a source, mesh,
material, transform, or render-object identity?

## Static hypothesis

The graphics-manager vtable begins at `0x007B8D4C`. Exact executable pointer
search and disassembly establish:

| Manager slot | Function | Static behavior |
|---|---:|---|
| `+0x138` | `0x006ABF80` | initializes/clears a source set and stores a value at manager `+0x554` |
| `+0x13C` | `0x006ABFB0` | stores a source pointer at manager `+0x558` |
| `+0x180` | `0x006ABFC0` | consumes four arguments and a polygon-list pointer, then calls slot `+0x184` |
| `+0x184` | `0x006AB410` | confirmed generic geometry accumulation |

Hypothesis: the source pointer, polygon-list pointer, immediate caller, or
preserved registers at the first three entries retain a stable identity above
the generic polygon boundary.

## Probe profile and filters

Run with `--profile m0-rt-002`. Only these addresses are armed:

| Event | Address | Captured data | Hit limit |
|---|---:|---|---:|
| owner_source_init | `0x006ABF80` | two arguments, manager source fields, caller and parent context | 256 |
| owner_source_ptr | `0x006ABFB0` | source pointer, first pointed value, manager source fields, caller and parent context | 256 |
| polygon_owner_entry | `0x006ABFC0` | four arguments, first polygon-list pointer, current source pointer, caller registers | 1,200 |
| geometry_submit | `0x006AB410` | four generic submission arguments, manager, Device3 and batch identities | 1,500 |
| batch_flush | `0x006AB380` | batch owner, counts and mode | 1,000 |
| draw_indexed_call | `0x006AB3C0` | native Device3 draw arguments and counts | 1,000 |

Maximum samples are 5,212, not 6,212: shared geometry/draw anchors plus the
three owner points. The runtime limit is 180 seconds. Exact address filters and
independent saturation are mandatory.

## Cleanup and hazards

Normal exit or timeout restores every armed byte before detaching. Never
terminate the debugger while the client continues running; close the client
first in an emergency. No executable or asset is modified on disk.

The runner must inherit elevation from the prepared parent shell because the
launcher-created client runs at higher integrity. Per-run sponsor UAC
confirmation is not part of the routine procedure. More than one matching
client process is a hard stop.

## Analysis and decision rule

Group each owner event by immediate return address, manager pointer, source
pointer, polygon-list pointer, argument shape, and preserved register values.
Then correlate event order into `geometry_submit -> batch_flush ->
draw_indexed_call`.

Promotion requires at least one semantic association corroborated by static
structure use plus differentiated runtime identity. Repeated pointers alone are
not proof of a ship or model. If all owner-level values are generic scratch or
transformed polygon storage, reject this level and use its finite caller set as
the next upstream candidates.
