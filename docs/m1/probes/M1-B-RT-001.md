## Question, hypothesis, and targeting

Can the semantic component intentionally change one rendered ship's primary
mesh color while two ships, the original geometry path, and tactical controls
continue normally, then return that same owner to its original appearance?

The [static analysis](../m1-b-visual-control-analysis.md) identifies RGB bytes
`+4/+5/+6` in 36-byte source entries, selected by polygon `+4` indices.
The **STRONG HYPOTHESIS** is that a magenta copy of those entries will visibly
tint the selected ship through original polygon preparation and vertex diffuse
packing. Static byte relationships are established; the visual effect is
unconfirmed. Lighting, material flags, textures, and secondary damage passes
may change its strength/coverage.

The target is the first validated mainline Model0 owner epoch. Validated
ship/visual/Model0 relationships and return `0x0042FDD5` are required; the
target is not presumed to be the player. Only that epoch on its original
render thread may be tinted. Retirement never automatically selects a new
epoch. The known `0x00509843` exception is left unchanged/unassigned.

## Component/ABI and reversible change

Component 0.3, additive `m1.semantic.v1` CSV fields; same five semantic hooks:
`0x0069E300`, `0x004162B9`, `0x0042FD3F`, `0x0042E4B2`, `0x0042FDD5`.
No new graphics hook; `0x006AB410` is not patched.

At Model0 entry, ECX is Model0, ESI the visual, stack argument 1 the manager,
and argument 2 the source. Original mainline return is `0x0042FDD5` and
`ret 10h` at `0x0042E64D` releases all four arguments. The existing thunk's
PUSHFD/PUSHAD/FXSAVE/FXRSTOR sequence is unchanged. Its saved ESP identifies
the original stack; only argument 2 is intentionally substituted.

The component reads primary polygon count `Model0+0x10` and list `+0x14`,
validates all indices, copies the referenced source prefix into a fixed
per-thread buffer, and sets only copied RGB bytes to `255/0/255`. Original
source storage, textures, modes, transforms, geometry, and executable files
are never written by this effect. The original Model0 method and downstream
rendering continue. Texture/lighting may modulate the tint.

At visual exit, manager `+0x558` is restored to the original argument only
if it still points to our copy. A renderer-authored replacement (for example
the Model0 damage pass's local source) is preserved. Stop prevents new
substitutions and waits up to five seconds for active copies to be released
through the still-installed exit hook. Failed release blocks hook removal;
normal game exit is the emergency rollback. The DLL/storage stays mapped
until normal process exit; do not force-unload or terminate the controller.

  begins after that signal, independently of the 600-second menu/gate wait.

  writing; no partial row crosses the cap. A summary warning flag records the
  16 MiB threshold. Fixed event storage and source buffers never grow.
