# M1-A-RT-001 — One-Owner Neutral Pass-Through

## Technical question and hypothesis

Can component version 0.1 occupy the confirmed semantic ship/model/mesh seam for
one visible tactical ship, correlate that owner to `0x006AB410`, preserve the
original render path and controls, then restore every changed byte?

**Hypothesis:** exact-byte inline trampolines with full x86/FX state preservation
will produce at least one valid owner/model/mesh chain and correlated downstream
geometry while the game renders and responds normally.

## Fixture and sponsor actions

Use `M1-A-FIXTURE-01`, the smallest available tactical setup with one visible
ship. If SFC cannot reliably provide a literal one-visible-ship fixture without
creating unrelated mission content, use the smallest known tactical fixture and
filter/adjudicate the first valid owner only; record the deviation rather than
inventing a mission feature.

Sponsor actions only:

1. launch SFC through the normal launcher;
2. enter the named minimal tactical fixture;
3. leave the ship/camera stationary for the brief bounded burst;
4. confirm rendering, HUD, cursor, and basic selection/control remain normal;
5. wait until the analyst reports component removal; and
6. exit SFC normally.

## Configuration and commands

First capture the paired disabled baseline:

```powershell
pwsh -NoProfile -File .\tools\m1_component\run_m1_increment_a.ps1 `
  -Mode disabled -MaxSeconds 120 -WaitForClientSeconds 600 -WaitForExitSeconds 600
```

Then, in a fresh SFC process, run enabled mode:

```powershell
pwsh -NoProfile -File .\tools\m1_component\run_m1_proxy_session.ps1 `
  -MaxSeconds 300 -WaitForClientSeconds 600 -WaitForExitSeconds 600
```

Start each runner before launching the corresponding fresh SFC process. Enabled
mode inherits the game's normal launcher elevation through the temporary proxy
and normally stops on the first detailed bound; do not pass
`-ContinueAfterBurst`.

## Start, stop, filters, and limits

- Start: exact client found and validated; enabled component installs before its
  automatic first-valid-ship tactical gate.
- Stop: 120 frames, 10,000 events, 300 seconds, controller error, or target exit.
- Owners: eight hard maximum; adjudication focuses on the first valid owner.
- Log: 16 MiB warning, 32 MiB hard stop.
- Downstream: `0x006AB410` detailed only inside the bounded burst; total counter
  remains available until removal.
- Expected enabled output: below 5 MiB total.

## Acceptance evidence

All are required for M1-04 completion:

- exact client hash before and after;
- component reports all hooks restored;
- controller independently reports `hook_bytes_restored=true`;
- at least one valid `tEntityShip -> t3DVisual_Model -> tModel0` opaque owner
  chain;
- at least one correlated `0x006AB410` event inside that chain;
- no owner/thread overflow, vtable mismatch, or log truncation;
- disabled/enabled visible rendering equivalent for the fixture;
- HUD/cursor/basic controls responsive;
- normal game exit after removal.

Failure or instability stops broader M1 testing. A generated analyzer PASS without
the sponsor-visible behavior and normal-exit evidence is insufficient.

## Output, cleanup, and raw-size hazard

Outputs and cleanup follow the shared runbook. Raw per-frame/per-draw tracing can
grow to multi-gigabyte files in minutes; this probe permits only the fixed event
buffer and summary counters. Do not substitute an unrestricted trace.
