## Contract and failure behavior

- New explicit `EnableRepeatedPrivateCopy=1` requires private-copy, wrapper and
  corner modes; default off. RT-007 entry still uses one substitution.
- Component 0.11 holds one original slot plus 31 additional fixed slots. Each
  graph slot is 20,512 bytes; bank including per-slot metadata must be <=700 KiB
  (compile-time assertion and runtime summary). No per-frame heap allocation,
  recycling, overwrite, retarget or growth. Slots are ordinary module data pinned
  until process exit, including in modes where extra slots remain unused.
- First eligible <=1,024-polygon primary call selects the owner epoch, thread,
  ship, visual, Model0, manager, source, original list and count. Later copies
  require all those identities to match, mainline depth one and first primary
  call in the Model0 scope. Other owners/LODs, secondary and unscoped paths bypass.
  Fresh owner epochs never inherit the selection, including pointer reuse.
- Each slot freshly copies the current complete list and up to 64 complete
  header/corner payloads, as RT-007. Preserve unknown bytes, UV and float bits;
  relocate only copied pointer locations. Tail polygon pointers remain original.
  This is not a complete model clone or a claim that source/tail lifetime changed.
- A subsequent handoff requires >=1,000 ms since the previous attempt, a matching
  preparation receipt and matching enclosing parent completion for that attempt.
  A pending slot token restricts receipt/parent accounting to its selected scope.
  Summary records capture frame, elapsed time, private address, shape, receipts,
  parent, failure, integrity and before/after fingerprints for every attempted slot.
- Identity mismatch leaves the call unchanged and increments a bounded counter;
  no substitution is attempted. Missing receipt/return blocks the next attempt.
  Build/publication failure or mismatched private-pointer receipt stops further
  substitution; original calls continue. Full bank also falls through unchanged.
- Previously published data is never cleared at parent return, retirement,
  saturation or hook stop. Module PIN remains until process exit. Controller
  forced unload remains refused before process access. Disabled means hooks
  restored but inert module/bank still resident; removed means game has exited.
