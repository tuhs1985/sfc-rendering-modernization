## Immutable publication / memory policy

SurfaceGraphPair is **332,336bytes** (<1MiB hard bound):eight64-polygon chunks per
graph, at most512 polygons; each has complete header/corner payloads and a complete
private list. Build once, never move/copy/overwrite either graph after qualification.
Graph pair carries canary/pointer/fingerprint integrity and exact expected-byte
comparison. Finite vectors required; nonzero vectors must actually change.

Before every graph publication, guarded reads compare current original count,
list, vertex count, original header addresses, header payload and all corner bytes
to the neutral baseline. Any change fails open; no stale geometry. Only call-local
list argument is redirected. Both immutable versions remain pinned until process
exit, including after their phase ends, owner retirement and hook restoration.
Repeated publication of immutable input is **not** recycling/overwriting a slot.
No need to infer an early-free point. No per-frame allocation or large fresh bank.
Existing legacy bank remains statically resident but unused by this mode; combined
copy storage remains <1MiB. Module/controller forced-unload guard retained.

Preparation receipts require the correct neutral/altered pointer, count, manager,
thread, owner and pending scope; matching parent closures/counters are required.

counts; wrapper/corner/rejection evidence retained. No per-call file transcript.
