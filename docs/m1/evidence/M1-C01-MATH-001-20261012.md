## Explicit math contract

Let R be three rows at transform offsets00/10/20 (three floats each), and t at
0C/1C/2C. Row storage/column-vector notation is our explicit algebra, not a claim
about a named graphics API. Scalar position output firstthree components:

`p_out = R p_in + t`

0069CBC0 computes `p_reverse = R^T (p_out - t)`;0069CC40 scalar branch computes
`v_reverse = R^T v`. Transpose is an inverse **only for orthonormal R**. A normal
under general affine A would require inverse-transpose; do not generalize this
sampled rigid-path conclusion to scale/shear. Position+6B0 is composed state,
not assumed pure world pose. Fourth output/68-byte metadata aren't treated as
normal data; script excludes DWORD17 from float-matrix interpretation.
